# 术语表（Glossary）

> **这是索引，不是教材。** 每个词的完整推导在对应章节，这里只给"一句话定义 + 一个数字锚点 + 一个常见误用"。
> 首次遇到某个词，请读对应章节；回来查的时候用这里。

---

## A. 规模与性能

| 术语 | 一句话定义 | 数字锚点 | 常见误用 |
|---|---|---|---|
| **DAU** | 日活跃用户数 | 2,000 万 | 与"注册用户"混用（1 亿注册 ≠ 2000 万 DAU） |
| **轮次（turn）** | 用户发一次、模型答一次 | 1.5 亿轮/日 | 把"会话"当"轮次"，差 5 倍 |
| **会话（session）** | 一次连续对话，含多轮 | 3,000 万会话/日（5 轮/会话） | 与会话有效期混为一谈 |
| **QPS** | 每秒**新到达**的请求数 | 峰值 7,000 | 当成"并发数"，差 3.5 倍 |
| **在飞请求** | 已到达但未完成的请求 | 2.5 万（3.5 s × 7000） | 与 QPS 混用；它才决定 KV 显存 |
| **并发连接** | 同时保持的连接数 | 62 万 | 拿它买 GPU，会多买 89 倍 |
| **Little's Law** | 在飞 = 到达率 × 停留时间 | 7000 × 3.5 s = 2.45 万 | 用它算"要多少卡"，它只算并发 |
| **p50 / p95 / p99** | 分位数延迟 | TTFT p95 ≤ 800 ms | 只报平均值，掩盖长尾 |
| **峰值系数** | 峰值小时占日量比例 | 12% | 抄别人家的，差 30% |
| **突发系数** | 峰值小时内再放大的倍数 | 1.4 | 与峰值系数重复计算 |
| **冗余系数（headroom）** | 为故障与突发预留的余量 | ×1.3（业务）+ ×1.2（双 AZ） | 只乘一次，漏掉 AZ |
| **可用区（AZ）** | 独立供电与网络的机房单元 | 2 AZ | 当成"异地多活" |
| **错误预算** | 1 − SLO，允许失败的额度 | 99.9% → 43.2 分钟/月 | 当成"可以随便花" |
| **单元化（cell）** | 把用户切片到独立小集群 | 单 cell ≤ 50 万 DAU | 与"多活"混为一谈 |

## B. 推理与模型

| 术语 | 一句话定义 | 数字锚点 | 常见误用 |
|---|---|---|---|
| **Prefill** | 一次性算完所有输入 token | 5,000 token / 450 ms | 以为它按 token 逐个算 |
| **Decode** | 逐 token 生成，每步重读权重 | 25 ms/token | 以为它算力受限（其实是带宽） |
| **TTFT** | 首 token 延迟 = 排队 + prefill + 网络 | ≤ 800 ms | 只算 prefill，漏掉排队 |
| **TPOT** | 相邻 token 间隔 | ≤ 50 ms | 与"端到端 ÷ 字数"混用 |
| **KV Cache** | 已算过的注意力键值，避免重算 | 120 KB/token（H800 TP8） | 按模型参数量估显存 |
| **PagedAttention** | 把 KV 切成固定块按需分配 | 块内浪费 <2% | 以为它省算力（它省显存） |
| **连续批处理** | 每步重组 batch，完成的退出、新来的加入 | decode 阶段天然等长 | 以为 prefill 也能这样 |
| **前缀缓存** | 相同前缀只算一次，命中直接复用 KV | 命中率 70% | 以为能省 decode |
| **RadixAttention** | 用基数树管理前缀缓存 | 系统提示词命中率 >90% | 以为跨租户可共享 |
| **Chunked Prefill** | 把长 prefill 切片，与 decode 混跑 | 切片 512 token | 切太小，调度开销吃掉收益 |
| **PD 分离** | Prefill 与 Decode 跑在不同卡池 | P:D ≈ 909:700 | 以为任何规模都值得拆 |
| **MFU** | 实际算力 ÷ 峰值算力 | 35% | 拿 100% 算容量 |
| **MBU** | 实际带宽 ÷ 峰值带宽 | decode 60%–70% | 与 MFU 混用 |
| **投机解码** | 小模型草稿 + 大模型校验 | 接受率 60%–80%，提速 1.5–2× | 以为无损（分布会偏） |
| **MoE / 激活参数** | 总参数大、每 token 只走部分专家 | 200B 总 / 30B 激活 | 用总参数算算力 |
| **Roofline** | 算力与带宽的瓶颈分界 | 脊点 590 FLOP/Byte | 以为 GPU 永远算力受限 |

## C. 平台与工程

| 术语 | 一句话定义 | 数字锚点 | 常见误用 |
|---|---|---|---|
| **Harness** | 模型之外、让 Agent 跑起来的那层工程 | 本书第 18–25 章 | 与"框架"混为一谈 |
| **Agent Runtime** | 把一次任务跑成可恢复状态机 | 单任务 ≤ 200 步 | 用无状态函数实现 |
| **事件溯源** | 只存事件，状态由重放得出 | 会话事件 ≤ 500 条 | 存快照当唯一真相 |
| **上下文窗口** | 一次能塞进模型的 token 上限 | 32K / 128K | 以为窗口大就能塞满 |
| **L0–L7 分层** | 上下文的八层组装 | L0 系统提示 ≤ 800 token | 把所有内容平铺 |
| **工具调用 / MCP** | 模型通过协议调用外部能力 | 单轮 ≤ 8 次工具 | 让模型直接执行代码 |
| **RAG** | 检索后拼进上下文 | Top-8，召回率 >85% | 以为能替代微调 |
| **背压** | 下游扛不住时向上游要减速 | deadline 逐跳递减 | 用无界队列"缓冲" |
| **熔断** | 连续失败后快速失败，不再打下游 | 5 次失败 / 10 s | 与限流混用 |
| **降级** | 主路径不可用时走次优路径 | 降级率 <5% | 降级后不监控 |
| **限流** | 主动丢弃超出配额的请求 | 令牌桶 3 QPS/用户 | 只在网关限，不管下游 |
| **幂等** | 同一请求重放结果不变 | 幂等键 = 会话+轮次 | 靠"应该不会重复" |
| **RPO / RTO** | 能丢多少数据 / 多久恢复 | RPO ≤ 5 min，RTO ≤ 30 min | 只做备份不做恢复演练 |

## D. 成本与运营

| 术语 | 一句话定义 | 数字锚点 | 常见误用 |
|---|---|---|---|
| **capex / opex** | 资本支出 / 运营支出 | 单节点 120 万 / 年运营 11.1 万 | 只算 capex 不算电与机位 |
| **折旧** | 硬件成本按年限摊 | 3 年，40 万/节点/年 | 按 5 年摊，低估成本 40% |
| **PUE** | 总用电 ÷ IT 用电 | 1.25 | 忽略不计（实际占电费 25%） |
| **单轮成本** | 总成本 ÷ 总轮次 | 0.52 分/轮 | 用"每百万 token"代替 |
| **口径（caliber）** | 分母的定义 | 总 token 0.97 元/M；输出 token 14.8 元/M | 对内对外用同一口径 |
| **毛利率** | (收入 − 成本) ÷ 收入 | 48%（2000 万 DAU） | 用规模化后的毛利算小规模 |
