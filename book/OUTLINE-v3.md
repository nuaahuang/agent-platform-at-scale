## 前言：为什么写这本书

### 给谁

| 读者 | 能拿到什么 |
|---|---|
| 后端/架构师转 AI 平台 | 一条可复制的完整链路：从 GPU 物理到计费对账 |
| 已在做 Agent 产品的团队 | 每一层的失败模式与验收标准，少踩坑 |
| 准备自建模型服务的企业 | 选型矩阵、容量模型、成本结构，可直接改参数复用 |
| 面试/答辩 | 40 章就是 40 个可深挖的技术点 |

### 两种读法

| 读法 | 章节 | 时间 | 目标 |
|---|---|---|---|
| **主线（建立体感）** | 1、2、8、10、11、13、15、18、19、20、21、23、24、26、31、32、35、39 | 2 周 | 能画出全链路并解释每个数字 |
| **全书（参考手册）** | 40 章 | 18 周 | 能独立设计并落地 |

### 每章固定结构

```
问题（真实故障/需求） → 原理（物理/协议/算法） → 设计（选型与取舍）
→ 数字（可复算） → 代码/配置（可跑） → 失败模式（怎么坏）
→ 验收（怎么证明对了） → 复盘卡（四行）
```

### 三条承诺

1. **每个数字可复算**：配套 `lab/` 脚本，改参数重跑；
2. **每个选型有 ADR**：选了什么、否了什么、什么条件下会推翻；
3. **每个组件可替换**：接口用标准协议，不锁死厂商。

## 关键补充 1：传统互联网模式映射（第 2 章）

| 经典模式 | 在 AI 服务里 | 结论 |
|---|---|---|
| 无状态水平扩展 | GPU 有状态（KV、前缀树），必须路由亲和 | **变形** |
| 连接池 | 到引擎的 gRPC/HTTP 池仍然必要 | 复用 |
| 本地/分布式缓存 | 响应缓存 → KV/前缀缓存；语义缓存慎用（错答风险） | **变形** |
| 消息队列削峰 | 请求排队 + 准入控制 | 复用 |
| 限流 | 从 QPS 变为 token/s + 并发会话数 | **变形** |
| 熔断降级 | 降级目标是"更小的模型/规则/人工" | **变形** |
| 多活/单元化 | cell 而非全局多活，KV 不跨区 | **变形** |
| 分库分表 | 会话按 tenant 分片，事件按时间分区 | 复用 |
| 幂等 | 工具调用有副作用，比传统写接口更关键 | 复用+ |
| 灰度发布 | 模型/Prompt/工具**三套**版本 | **扩展** |
| 压测 | 不能只按 QPS，要按 token 长度分布 | **变形** |
| 重试 | 重试放大 GPU 与 token 成本，必须预算化 | **慎用** |
| 数据库事务 | LLM 调用不可回滚，用 saga/补偿 | **失效** |
| 长轮询 | SSE/WebSocket 替代 | 复用 |

**一句话**：传统互联网是"请求-响应 50ms、无状态、可重试"；
AI 服务是"请求-流式 9s、有状态、重试昂贵"——**这三点差异推翻了半数经典假设**。

## 关键补充 2：全链路背压分层（第 24 章）

| 层 | 压力信号 | 动作 | 超时预算 |
|---|---|---|---|
| 客户端 | 用户取消/切页/断网 | 取消信号上传，释放 GPU | — |
| 网关 | 租户配额、全局水位 | 429 / 排队 / 降级 | 100ms |
| BFF/会话 | 单会话步数、token 预算 | 截断、强制收尾 | 每步 30s |
| Harness | 工具时延、重试次数 | 跳过工具、转人工 | 工具 10s |
| 调度器 | 队列长度、KV 水位 | 拒绝新请求 / 降级小模型 | 1s |
| 引擎 | running/waiting batch | 拒单 / 抢占低优先级 | — |
| GPU | 显存、KV 碎片 | 驱逐、LRU、拒绝 | — |

**五条铁律**：

1. **deadline 逐跳递减**：上游给 3s，下游最多 2.5s，不允许"每层都等 3s"；
2. **背压信号单向向上**，不能靠轮询；
3. **禁止无界队列**：队列长度必须是显式配置；
4. **重试必须有预算 + 抖动 + 上限**，否则重试风暴打穿 GPU；
5. **谁能拒绝谁要写清楚**：网关可以拒用户，引擎不能拒网关（否则雪崩）。

## 关键补充 3：存储四件事（第 26–29 章）

| 主题 | 关键决策 | 数字/机制 |
|---|---|---|
| 分层 | 热（Redis/MySQL）→ 温（CH/Iceberg）→ 冷（S3） | 会话 30 天热、1 年温、3 年冷 |
| 分片 | tenant_id 哈希 + 时间分区 | 单表 < 2000 万行；扩容 double-write + 校验 + 切读 |
| 备份 | 周全量 + 日增量 + binlog PITR | RPO ≤ 5min，RTO ≤ 30min，季度演练 |
| 安全 | TDE + 字段级加密（手机号/地址）+ KMS 轮转 + 审计 + WORM | 密钥 90 天轮转，删除权 30 天内完成 |

**扩容剧本（不停机）**：加节点 → 双写 → 全量校验 → 影子读 → 切读 10%→50%→100% → 下线旧分片。
每一步都有回滚点。

**备份不是"有备份"，是"演练过恢复"**：每季度随机抽一个分片做真实恢复，
记录实际 RTO，写进报告——没演练过的备份等于没有备份。

| 离线/训练数据 | **Python + Spark** | — | 生态 |

| 策略 | OPA / Kyverno | — | 标准 |

**分工原则**：IO 密集用 Go，业务编排用 Python/Java，数据用 Java/Scala/Python，
引擎侧 Python/C++。**禁止一套语言打天下**——代价是运维复杂度，收益是每层都用对的工具。
