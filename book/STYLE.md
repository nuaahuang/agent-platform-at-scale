# 写作标准（STYLE）

> 本标准不是"建议"，是**合并门槛**。`make style` 不过的章节不进 main。
> 阈值来自已完稿章节的实测分布（见文末"阈值怎么来的"）。

---

## 0. 一句话标准

**每一段都要能被追问"凭什么"，并且答案是一个数字、一段代码、或一个可复现的实验。**

达不到就是不达标，不管写得多流畅。

---

## 1. 每章骨架（八段，缺一不可）

| 段 | 要求 | 反例 |
|---|---|---|
| 1 问题 | 真实故障或具体需求，带现象 | "随着业务发展，性能成为瓶颈" |
| 2 原理 | 物理/协议/算法层面的因果链 | "因为框架优化了内存" |
| 3 设计 | 选了什么、**否了什么**、代价是什么 | 只讲选中的方案 |
| 4 数字 | 可复算，标注脚本与参数 | "性能提升明显" |
| 5 代码/配置 | 能跑或能 apply | 伪代码占位 |
| 6 失败模式 | 现象 → 根因 → 怎么发现 → 怎么修 | 只写正常路径 |
| 7 验收 | 指标 + 阈值 + 怎么测 | "测试通过" |
| 8 复盘卡 | 四行，见 §6 | 无 |

> 允许合并小节（如"原理+设计"），但**八件事必须都出现**。

## 2. 五个硬阈值

| 指标 | 阈值 | 实测中位数 |
|---|---|---|
| 数字密度 | ≥ 45 个/百行 | 71 |
| 表格行 | ≥ 25 行 | 80 |
| 代码/ASCII 图块 | ≥ 3 个 | 10 |
| 小标题 | ≥ 10 个 | 21 |
| 正文字数 | ≥ 5000 字 | 8000 |

低于阈值通常意味着两件事之一：**要么没算，要么在灌水**。

## 3. 十二条写法规则

**R1 结论先行，加粗**
第一句就把结论说出来，后面才是推导。

> ❌ "我们先分析一下各种因素，然后综合考虑……"
> ✅ "**别按 GPU 利用率扩容。** 它高可能是 batch 大，也可能是排队。"

**R2 每个形容词后面必须有数**
"大幅""显著""明显"单独出现即违规。

> ❌ "PagedAttention 大幅降低了显存碎片。"
> ✅ "PagedAttention 把块内碎片从 73.7% 降到 0.4%（`labs/paging_lab.py`，2000 条会话）。"

**R3 选型必须写"否了什么"和"推翻条件"**

> ❌ "使用 Kafka 作为消息队列。"
> ✅ "选 Kafka 而非 Pulsar：Flink 生态成熟、团队已有运维经验；代价是每年 2 次滚动升级窗口。
> 推翻条件：需要跨地域强一致流时改 Pulsar。"

**R4 单位必须能消去**
公式里每个量的单位写出来，最后一步做量纲检查。

> ✅ "1.5e8 轮/日 ÷ 86400 s × 0.12 × 1.4 = 2917 QPS"（轮/日 ÷ s/日 = 轮/s）

**R5 口径先于结论**
同一件事有多种算法时，先列口径，再给数。

> ✅ "三个口径：62 万连接 / 2.5–6 万请求 / 7000 QPS——差 10 倍，因为分母不同。"

**R6 用表对比，不用段落罗列**
三个以上对象的比较一律上表，列固定为：对象 / 关键数字 / 代价 / 适用条件。

**R7 机制必须画出来**
内存布局、请求时序、状态机、数据流——至少一张 ASCII 图。

**R8 失败模式单独成节**
格式固定：`现象 → 根因 → 怎么发现（指标）→ 怎么修（动作）`。

**R9 主动纠正一个常见误解**
每章至少有一个"以为…其实…"的对照。

> ✅ "以为 decode 也要 padding；其实 decode 每步只处理 1 个 token，天然等长。"

**R10 数字给区间，不给单点**
延迟、成本、命中率这类量，给 p50/p95 或"基准±敏感性"，不给一个孤零零的数。

**R11 外部事实必须有链接**
版本号、参数、厂商声明，一律附来源；推断必须标注"推断"。

**R12 结尾一句话收口**
用一句可记住的话总结，不写"综上所述"。

## 4. 数字的三条纪律

1. **保守取值**：不确定时取更差的那个，并在文中写明"这是保守估计"；
2. **可复算**：正文写脚本名 + 关键参数，读者改参数能重跑；
3. **标注假设**：采购价、命中率、峰值系数这类外部输入，单独列"假设表"。

---

## 5. 禁止词表（出现即不合并）

| 类别 | 词 |
|---|---|
| 空话 | 赋能、抓手、闭环生态、全面提升、业界领先、颠覆、革命性 |
| 无量形容词 | 大幅、显著、明显、极大、成倍（后面没数字时） |
| 含糊量词 | 很多、一些、大量、较快、比较好、相当（应给具体值） |
| 万能句 | "随着业务发展"、"在当今时代"、"众所周知" |

---

## 6. 复盘卡格式（每章结尾固定四行）

```
一句话：这章到底解决了什么
我算的：我亲手算出的一个数（含单位）
我原来以为…实际…差在：
还没懂：
```

## 7. 自检流程

```bash
make style          # 全部章节

```

检查项与阈值一一对应，失败会打印具体数字与差额。
