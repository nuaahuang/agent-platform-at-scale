## 这本书解决什么问题

大多数 Agent 教程停在"prompt + 工具 + 循环"，上不了生产。真正卡住人的是下面四件事：

1. **算不清**：2000 万 DAU 要多少卡、多少钱、瓶颈在哪一层；
2. **跑不稳**：进程在第 37 步崩了、工具重复调用、模型突然变慢，怎么恢复；
3. **扛不住**：从客户端到 GPU，压力信号怎么逐跳传导，谁该拒绝谁；
4. **算不明**：Token 花在谁身上、怎么定价、怎么对账、怎么防烧穿预算。

这本书把 **模型工程 → 推理工程 → Harness → 应用接入 → 数据存储 → 高可用 → 安全合规 → 运营**
串成一条可验收的链路，每一层都给：决策、数字、失败模式、可运行代码、验收标准。

> 不做训练。预训练、并行策略、RL 算法请移步 [diy-llm](https://github.com/datawhalechina/diy-llm)。
> 本书只保留"影响架构决策"的那部分模型知识：怎么选、怎么评、怎么压、怎么灰度。

## 每一章长什么样

```
问题（真实故障/需求） → 原理（物理/协议/算法） → 设计（选型与取舍）
→ 数字（可复算） → 代码/配置（可跑） → 失败模式（怎么坏）
→ 验收（怎么证明对了） → 复盘卡（四行）
```

三条承诺：

1. **每个数字可复算** —— `labs/` 里改参数重跑；
2. **每个选型有 ADR** —— 选了什么、否了什么、什么条件下推翻；
3. **每个组件可替换** —— 接口用标准协议，不锁死厂商。

## 快速开始

```bash
# 0) 检查写作标准（每章必须过关）
make style

# 1) 算一遍容量与成本（纯标准库，无需依赖）
python3 labs/calc.py
python3 labs/pd_cost_lab.py

# 2) 跑通最小链路：网关 → mock 引擎 → SSE
python3 platform/gateway.py --port 8080
curl -N "http://127.0.0.1:8080/v1/chat?tenant=demo&q=我想退货"
```

## 写作标准（底线硬，形式软）

**三条硬底线**，不满足不合并：

| 底线 | 判据 |
|---|---|
| 不写空话 | 无"赋能/抓手/闭环生态"等禁止词 |
| 结论有依据 | 数字、代码、引用、实验，至少一种 |
| 写清边界 | 什么情况下不成立、失败长什么样 |

**结构自由**：不强制八个标题，只要求读者能回答八个问题（问题/机制/选型/代价/验证/失败/备选/收口），
推导式、决策式、清单式、问答式都合法。

**密度是参考区间，不是及格线**：

| 类型 | 字数 | 数字/百行 |
|---|---|---|
| 概念型 | 3,000–6,000 | 15–40 |
| 标准型 | 6,000–10,000 | 40–80 |
| 密集型 | 8,000–14,000 | 70–120 |

低于区间可以，但要在章首声明 `> 本章为概念型，重点在判断而非测算`。
细则见 [book/STYLE.md](book/STYLE.md)。

```bash
make style          # 硬底线（CI 用这个）
make style-strict   # 终稿：密度不足也算失败
```
