011. 问题：一套 Python 打天下，网关先崩

一个真实的重构：团队全是 Python 背景，于是网关也用 FastAPI 写。

上线后的三个数：

指标Python 网关Go 网关差距
单机 QPS（8 核）8,00060,0007.5×
单实例内存300 MB50 MB6×
p99 抖动（GC）40 ms3 ms13×

按 7,000 QPS 峰值算：

不是 Python 不行，是每个位置有它的最优语言。网关的活是"每毫秒转发十万个连接"，Python 的 GIL 与对象开销天生不适合；模型服务的活是"调 CUDA kernel"，Python 只做控制面，那 5% 的开销就无所谓。

022. 判据：按延迟预算与并发形态分工

选语言只看两个变量：这个位置的延迟预算是多少、并发是什么形态。

位置延迟预算并发形态选它理由
网关 / BFF<5 ms高并发短连接Go协程轻、内存小、启动快
Harness 编排10–100 ms长事务、IO 密集PythonLLM SDK、生态最全
工具沙箱100 ms–10 s不可信代码Go隔离好、可控
模型服务25 ms/stepGPU 密集Python + CUDA引擎生态绑定
计费 / 账务批处理强一致事务Java事务与金融生态
数据管道分钟级批 / 流Python / Scala生态
运维工具无一次性Go单二进制，无依赖

一句话：延迟越紧、并发越高 → 越往 Go 走；越靠近模型与数据 → 越往 Python 走；越涉及钱和事务 → 越往 Java 走。

033. 三套语言的边界：只走协议，不共享内存

三条纪律：

纪律原因
跨语言只走 gRPC/HTTP不共享内存，不做 FFI（Foreign Function Interface，进程内跨语言调用）
proto 是唯一真相三语言各自生成代码，不许手写结构体
跨边界调用要少gRPC 一次 0.2–0.5 ms，本地调用 0.1 μs，差 5,000 倍

第三条最容易违反：如果按 token 逐次跨语言调用，单次 0.3 ms × 300 token = 90 ms，比整个 TPOT 预算还大。所以流式必须批量推送（每 10–20 token 一批）。

注意
注意 FFI 的例外：引擎内部到处都是 FFI——Python 调 C++ 调 CUDA kernel，
那是同一进程、同一生命周期、同一发布节奏，代价可接受（第 10A 章）。
业务层不用 FFI，是因为两侧要独立扩缩容、独立发布、故障互相隔离。

044. 为什么模型服务只能是 Python

事实说明
vLLM / SGLang / DeepInfer 都是 Python 控制面调度器、block manager、API 层
热点在 C++/CUDAattention、GEMM、通信全是编译产物
Python 开销占比<5% 的 step 时间（第 10A 章实测口径）

推翻条件：如果你要做极致定制（自研调度器、极致延迟），可以把控制面重写成 C++——TensorRT-LLM 的 C++ runtime 就是这么做的。代价是失去 Python 生态（评测、工具、调试）。

对 99% 的团队，不值得。

4.1 真正难的不是选语言，是锁版本

模型服务的依赖链比业务服务脆得多，任一层错配就是编译失败或运行崩：

层约束错配后果
驱动≥ 535（CUDA 12.2+）装不上 CUDA 12.4
CUDA与 PyTorch 编译版本严格绑定undefined symbol
PyTorch与 vLLM 版本绑定引擎启动即崩
vLLM与 flash-attn / xformers 绑定kernel 不可用
flash-attn必须现编，20–40 minCI 时间失控

做法：整条链打进一个镜像，锁死 digest，CI 只认这个 digest。不要在生产机上 pip install —— 一次升级会连锁破坏三个包。

066. 自研还是用现成

能力现成方案什么时候必须自研

判据：能用扩展点解决的，绝不 fork。fork 一个中间件，三年后升级不了。

6.1 一个真实的选型过程

需求：事件总线要支撑 1.5 亿轮/日的会话事件与计费流水。

候选吞吐延迟运维结论
RabbitMQ5 万 msg/s1 ms简单❌ 吞吐不够
Pulsar100 万 msg/s5 ms需 BookKeeper❌ 多一套存储要运维
Kafka100 万 msg/s5 ms成熟✅ 够用且团队会

否掉 Pulsar 的理由不是性能，是"多一套 BookKeeper 要三个人维护"。选型的胜负手经常不在技术指标，在运维成本。

077. 团队规模：AI 之后要重算

7.1 旧模型错在哪

上一版这张表是按"每个中间件一个 owner、每种语言一个专家"算的：

旧假设后果
8 个中间件 → 8 个 owner直接把人数抬到 20+
3 种语言 → 3 组专家再翻一倍
7×24 值班 → 每班 2 人至少 10 人

这套算法在 AI 辅助编程之前是对的，现在前两条已经不成立：中间件的部署、升级、排障样板代码，AI 几分钟就能生成；跨语言也不再需要"专家"，需要的是"能 review 的人"。

7.2 什么被压缩了，什么没有

工作AI 压缩倍数说明
写新代码5–10×样板、CRUD、配置、测试
读陌生代码3–5×快速定位与解释
写文档5×从代码反推
Code review1.2×人必须真的看懂
On-call 值班1×半夜叫醒的是人
决策与定责1×选型错了谁签字
跨部门协调1×安全、合规、采购

结论：建设期人力断崖式下降，运行期几乎不变。

7.3 修正后的人数

阶段规模建设（AI 辅助）运行（值班 + 变更）合计
0→1 原型1 万 DAU / 16 卡20（自己兼）2
1→10 产品化100 万 DAU / 128 卡314
10→100 规模化1,000 万 DAU / 1,024 卡538
亿级2,000 万 DAU / 2,512 卡7411

对照上一版：亿级平台从 100 人降到 11 人，差 9 倍。

但 11 人里 4 个是值班，不是写代码——这个比例很说明问题。

7.4 真正的瓶颈：两端没动，中间塌了

把交付拆成五段，AI 只压缩了中间：

环节AI 加速为什么它仍是瓶颈
需求理解1.5×AI 能帮你整理需求，但判断"用户到底要什么"必须是人
设计1.5×AI 给得出五个方案，拍板与担责只能是人
实现10×已经不是瓶颈
代码 review1.2×部分可自动化（测试、lint、AI 初审）
目标验证1.2×"跑通了" ≠ "对了"

第 5 段是全章最容易被低估的：代码能跑、测试全绿、指标正常，但结果不是你要的。

LLM 平台尤其如此——输出没有绝对正确，只有"符合预期"。所以要靠：

手段回答什么
黄金用例集（50 条）该对的是不是还对
影子对拍新旧版本差异在哪
人工抽检机器判不了的"感觉对不对"
灰度指标真实用户是否买账

7.5 一个人的产能上限

工作一周能做多少为什么不能更多
设计决策（有取舍、有推翻条件、有验收）2–3 个每个都要想清楚约束与代价
目标验证（定义判据 + 跑 + 判断）3–5 个每个都要对照目标而不是对照代码
写代码数千行已经不是限制

推论：团队规模 = 能同时推进的设计决策数，不是能写多少代码。

这就是为什么本书每章都强制有"验收"一节——验收就是"目标验证"的载体，把它写进文档，才不会退化成"测试跑过了就算完"。

7.6 语言数量的结论也要改

旧结论是"语言数量 ≤ 团队能维护的边界数量，5 个人 3 种语言会半吊子"。

现在这个约束松了：AI 能让一个人写出合格的 Go 和 Python，但松不了的是"出故障时谁能定位"。

旧约束新约束
每种语言要有专家每种语言要有能半夜看日志的人
语言数 ≤ 团队容量语言数 ≤ 值班人数

所以 5 人团队上 3 种语言仍然危险——不是因为写不出来，是因为凌晨 3 点没人看得懂。

099. 失败模式

现象根因怎么发现怎么修
网关 CPU 打满用 Python 写网关top 单核 100%换 Go / Envoy
跨语言调用成瓶颈每 token 一次 RPCtrace 里 RPC 占比 >30%批量推送
三种语言三种日志格式没有统一打点排障时要翻三个系统统一 OTel schema
proto 不兼容删字段 / 改类型老客户端报解析错只增不删 + CI 检查
中间件太多没人会每个能力都选最强故障时无人能修砍到 6 个以内
团队都会一点语言数 > 团队容量PR 评审质量下降收敛到 2–3 种

1010. 验收

检查项通过标准
网关语言非 Python（Go 或 Envoy）
跨语言调用流式按批（≥10 token/次），非逐 token
proto 兼容CI 里有 breaking change 检查
中间件数量≤8 个，每个有 owner（AI 可代劳部署，责任不能代劳）
选型文档每个都写了"否了什么 + 推翻条件"
语言数量≤3 种，且每种语言有 ≥2 人能值班定位

最后一条是给技术负责人的：每多一种语言，就多一套 CI、监控、on-call——AI 能帮你写，但替不了你凌晨三点看日志。

1111. 备选方案：全用一套语言会怎样

方案优点代价
全 Python招聘统一、生态好网关 QPS 差 7.5×，内存 6×
全 Go性能好、部署简单缺 LLM 生态，模型侧要重写
全 Java事务强、企业生态模型侧几乎无生态，启动慢
Go + Python（推荐）各取所长，两种够用需要 proto 契约纪律

推荐：Go（网关/工具）+ Python（模型/Harness），计费到了 30 人再加 Java。

1212. 收口

**语言不是信仰问题，是延迟预算问题。

谁的预算最紧谁用 Go，谁离模型最近谁用 Python，谁管钱谁用 Java。**
