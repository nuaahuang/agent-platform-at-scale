011. 问题：老板要降 30%

第 13 章算出 2,512 卡、年成本 2.83 亿。季度会上老板说，明年预算砍 30%，也就是省 8,500 万。

工程侧的反应通常是"优化推理效率"。但先把账拆开看，会发现方向可能不对：

类别年成本占比
折旧2.39 亿84.5%
运营0.44 亿15.5%
合计2.83 亿100%

84.5% 是固定资产折旧，不是运行开销。 这意味着：

  • 把电费压到零，也只省 5.7%
  • 把推理效率提升一倍，省的是一半的卡，也就是一半的折旧
  • 但卡已经买了，折旧照提，只有在"不再买新卡"的时候才真正省钱

这条决定了降本的顺序：先动"卡数"，后动"每卡的开销"。

2.1.1 为什么按三年折旧

三年不是寿命，是经济寿命。这三个概念要分开：

寿命多长由什么决定
物理寿命5–7 年风扇、电容、HBM 的磨损
会计折旧3–5 年财务与税法口径
经济寿命2–3 年新一代卡的性价比

物理上 H100 跑七年没问题。问题是第三年的时候，新一代卡在同样功耗下算力可能翻一倍，你的旧卡不是坏了，是"同样的活它贵一倍"。

所以三年折旧对应的是主力期。三年之后卡还在跑，只是不在主推理池里了。它的去向有四级：

去处干什么还能用几年
训练池训练对延迟不敏感，旧卡划算1–2 年
离线批处理回刷、报表、评测1–2 年
二手市场残值 15%–25%—
价格敏感的租户便宜卖视市场

换个折旧年限，账差三分之一：

折旧年限年成本单卡时单轮成本
3 年2.83 亿¥12.860.517 分
4 年2.23 亿¥10.150.408 分
5 年1.87 亿¥8.520.342 分

五年折旧的数字好看得多——单轮便宜 34%。但这个数字有前提：第五年时这 2,512 卡还在满负荷跑主力任务。

如果实际第三年就被新卡挤到训练池，那后两年的真实产出只有前两年的一半，按五年的账算出来的"便宜"是假的，实际是把成本挪到了后面，同时还要承担一次资产减值。

所以选三年有两个理由：

第一，保守。不把未来的算力红利算进今天的成本。如果实际用了五年，那第四、五年就是白赚，成本低于模型预测；反过来（按五年算、三年就淘汰）是一次性减值，财报上很难看。

第二，和采购节奏对齐。一年一采的话，每批卡的价格和性能都不同，按三年折完正好可以重新评估"这批要不要换"。

反过来也有例外：如果业务确定不会因为新卡而迁移（比如给内部用的固定小模型），卡会用到物理寿命，那按五年折旧更准确。判断方法只有一个——看历史上你换卡的平均间隔，而不是看新卡发布的节奏。

按三年直线折旧，年折旧 2.39 亿。按三年直线折旧，年折旧 2.39 亿。

这个数还能往下拆：一轮里 prefill 和 decode 各花多少？

环节卡数年成本单轮成本
prefill9091.03 亿0.188 分

冗余与弹性9031.01 亿0.185 分
合计2,5122.83 亿0.517 分

冗余那 903 卡摊到每一轮是 0.185 分，占 36%。 这一行常被忽略：它不是"浪费"，是可用性的价格，但它确实占了三成六的单轮成本。

043.5 三个视角看同一个成本

0.517 分/轮 是内部口径，对外沟通要用另外两个：

视角数值怎么算
每轮0.517 分2.83 亿 ÷ 547.5 亿轮
每百万输入 token¥2.722.83 亿 ÷ 1.04 亿个百万 token
每百万输出 token¥14.72.83 亿 ÷ 1,920 万个百万 token
每个 DAU 每年¥14.22.83 亿 ÷ 2,000 万

输入和输出差 5.4 倍，是因为一轮里输入 1,900 token、输出 350 token，但 prefill 的算力占比只有 36%。这个差值是定价的基础——第 17 章讲按 token 定价时，输出单价必须高出输入 3 倍以上。

每 DAU 每年 ¥14.2 这个数最容易被追问。它的含义是：一个日活用户，一年消耗 14 块钱的算力。如果客单价低于这个数的两倍，商业模式不成立。顺着这三个数会引出一个问题：输入和输出为什么不同价？这里要先说清摊法。prefill 池的成本有两种摊法：摊到全部输入 token 是 ¥0.99，摊到真正被计算的未命中 token（只占 15%）是 ¥6.56。两种都成立，差 6.6 倍。下表用第一种（平均摊），它对应的是对外的混合输入价：

环节年成本年 token 量每百万 token
prefill1.03 亿104 万亿¥0.99
decode0.79 亿19.2 万亿¥4.13

差价不是定价策略拍出来的，有三个物理来源。

第一，输入可以缓存，输出不能。前缀命中率 85%，意味着输入里只有 15% 真正进了计算；而每一个输出 token 都必须现算。这一条单独就能解释 6.7 倍。

第二，输出 token 占着 KV 不放。350 个输出 token 按 22.4 ms 一步算，要占 7.8 秒的 KV；输入 token 算完就释放，只留 KV 不留计算资源。

第三，两个环节的瓶颈根本不同。prefill 拼的是算力利用率（MFU 45%），decode 拼的是 KV 容量和带宽。所以给 prefill 加卡能线性提吞吐，给 decode 加卡只是多装几个请求。

这三条加起来是 4.2 倍。市场上主流定价在 3 到 5 倍之间，说明大家的成本结构差不多。

定价时还要加一层商业考虑：输入是用户提供的原材料，输出是产品。所以实际挂牌价往往在成本比之上再加一点，第 17 章会算这笔。

053.6 三年曲线：单位成本会自己降

固定成本摊薄是规模效应里最实在的一条。假设每年流量涨 50%，卡数按需增加，但机房、人力、网络这些半固定项涨得慢：

年流量卡数年成本单轮成本
Y11.0×2,5122.83 亿0.517 分

Y32.25×3,6003.81 亿0.310 分

三年下来单轮成本降 40%，靠的不是技术进步，是固定成本被摊薄。

KV 从 FP16 降到 FP8，单请求占的空间减半，单实例并发翻倍，decode 卡数从 700 降到 350：

代价在长上下文：16K 以上掉 1.5–3 个点（第 6 章）。如果业务以长文档为主，这条不能做。

5.3 削峰：少买 20% 的卡

峰值系数从 4.0 降到 3.2，卡数等比缩 20%：

怎么降？两条路：排队（超出容量时让用户等）和预约（把非紧急任务挪到低峰）。代价是峰值时段 30–60 秒的排队，会流失一部分用户。

这一条最容易被低估：它不是技术活，是产品决策。签字的应该是业务负责人，不是 CTO。

086. 降本的质量代价要标出来

每一条降本都在拿某种东西换钱，必须写清楚换的是什么。

措施换掉什么可观测指标谁签字
分流 8B少量准确率分流后重跑率算法负责人
KV FP8长上下文精度16K+ 通过率算法 + 产品
削峰峰值体验排队时长 p99业务负责人
冗余 1.40故障时的余量单 AZ 故障演练结果SRE
议价供应商关系交付周期采购

没有"免费的降本"。如果某条措施声称没有代价，多半是代价还没显现——比如分流器在测试集上 95%，上线三个月后分布漂移掉到 88%。

096.5 一个能落地的降本排期

十条措施不能同时上，会互相干扰观察。按季度排：

季度做什么预期省验证方式
Q1KV 量化 FP8 + 长上下文分桶回归6,170 万16K+ 通过率不掉 2 点
Q2分流器上线，先 10% 流量2,000 万（部分）重跑率 < 5%
Q3分流放到 40% + 削峰排队1.1 亿（累计）排队 p99 < 60 秒
Q4冗余从 1.56 调到 1.40 + 议价4,100 万单 AZ 故障演练通过

每季度只动一类，是为了能归因。同时上量化和分流，卡数降了，但说不清是谁的功劳，下次也不敢再动。

排期的另一个约束是采购节奏：卡是一次性买的，降本效果要等到下一轮采购才体现。所以 Q1 省下的 6,170 万，在 Q1 的财报上看不到，只在 Q3 的采购预算里体现。这一层要提前跟财务对齐，否则会被认为"降本没效果"。

1411. 复盘卡

我原来以为降本是压低"每卡开销"，实际差在八成的钱压在折旧上——不减少卡数，优化电费和运维都是小数点后的功夫。
